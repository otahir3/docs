The MarketBox API lets you build, schedule, and manage bookings and orders
from your own systems — the same primitives that power the MarketBox
dashboard, exposed as a stable, versioned HTTP surface.

## What you can do

<CardGroup cols={2}>
  <Card title="Bookings" icon="calendar-check" href="/resources/bookings">
    Create, reschedule, cancel, and check in on bookings. Manage participants
    and notes attached to each booking.
  </Card>
  <Card title="Orders" icon="receipt" href="/resources/orders">
    Build orders for a client, add or remove line items, change order status,
    and look up an order's items.
  </Card>
  <Card title="Offerings" icon="tags" href="/resources/orders">
    Read the service offerings available in a project — name, price,
    duration, attributes, and status. Referenced from order and
    booking line items.
  </Card>
  <Card title="Providers" icon="user-tie" href="/resources/providers">
    Read providers in a project, enriched with their services and skills.
  </Card>
</CardGroup>

## Conventions at a glance

- **Base URL**: read from `$MARKETBOX_API_URL` — see [Base URL](/api-reference/introduction#base-url)
- **Versioning**: every resource path is prefixed with `/v1`.
- **Auth**: API key in the `x-api-key` header. See [Authentication](/concepts/authentication).
- **Pagination**: opaque cursor + `limit`. See [Pagination](/concepts/pagination).
- **Errors**: structured envelope with `code`, `message`, `statusCode`, `requestId`. See [Errors](/concepts/errors).
- **Time**: every booking carries explicit UTC instants plus an IANA timezone. See [Timezones](/concepts/timezones).
