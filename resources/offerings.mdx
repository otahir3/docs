---
title: Offerings
description: The catalog of bookable / orderable items in a project.
---

A **service offering** is one row in the catalog of things a client can
book or buy. Each offering belongs to a `service`, and a `service` may
have many offerings (different durations, formats, prices).

The public API exposes offerings as a **read-only** surface: you list
what's available in a project. Creating or editing offerings happens in
the MarketBox dashboard.

## Anatomy

An offering combines:

| Field             | Notes                                                                |
| ----------------- | -------------------------------------------------------------------- |
| `offeringId`      | Unique within its service.                                           |
| `serviceId`       | The parent service. Multiple offerings can share a `serviceId`.      |
| `name`            | Display name.                                                        |
| `price`           | A `Money` value — `{ amount: number, currency: string }`.            |
| `duration`        | Either `{ type: "FIXED", minutes }` or `{ type: "RANGE", defaultMinutes, minMinutes, maxMinutes }`. |
| `attributeValues` | Free-form attributes that distinguish variants of the same service.  |
| `status`          | `ACTIVE`, `INACTIVE`, or `DELETED`. Only `ACTIVE` is bookable.       |

`amount` is an **integer in the currency's minor unit** (cents for USD,
pence for GBP, etc.). MarketBox never represents money as a float.

## Status

| Status     | Meaning                                                            |
| ---------- | ------------------------------------------------------------------ |
| `ACTIVE`   | Bookable and orderable. The only status that creates succeed for.  |
| `INACTIVE` | Hidden from new bookings/orders but existing references survive.   |
| `DELETED`  | Soft-deleted; will not appear unless you explicitly filter for it. |

Trying to create a booking or order against a non-`ACTIVE` offering
returns:

```json
{
  "code": "OFFERING_NOT_BOOKABLE",
  "message": "Offering off_xxx is not bookable (status: INACTIVE)",
  "statusCode": 400,
  "requestId": "req_..."
}
```

## Listing offerings

```
GET /v1/projects/{projectId}/offerings?status=ACTIVE
```

Query parameters:

| Param     | Default     | Notes                                                |
| --------- | ----------- | ---------------------------------------------------- |
| `status`  | — (all)     | Filter by status. Most consumers want `ACTIVE`.      |
| `limit`   | 50          | Page size. Max 200.                                  |
| `cursor`  | —           | Pagination cursor. See [Pagination](/concepts/pagination). |

The list is ordered **newest first** by creation time within the
project.

## Snapshot semantics

When you create a booking or add an order item, the API reads the
referenced offering and **freezes** the relevant fields into the
booking line / order item:

- `name`, `price`, `duration`, `attributeValues` are all snapshotted.
- The snapshot is stored on the booking service / order item.
- Subsequent edits to the offering do not propagate to existing
  bookings or orders — they only affect new ones.

This is why offerings are read-only via the open API: edits would
otherwise affect downstream records' assumed prices and durations.
