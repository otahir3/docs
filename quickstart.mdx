This guide gets you from zero to a working call against the MarketBox API.

## 1. Mint an API key

API keys are minted from a project's [**API Access** page](https://mb-core.vercel.app/dashboard/project/{projectId}/api-access/)
in the MarketBox dashboard. Each key has:

- A **friendly name** — human-readable label.
- A **project scope** — the projects this key can act on.
  - `["*"]` means "every project the owner can access".
  - `["prj_01h2xcejqtfzcjxkvc4ay3pnh3"]` restricts the key to that project.

Treat the key like a password. Anyone who has it can act on the projects in
its scope. Rotate or revoke from the dashboard at any time.

<Warning>
Never commit API keys to source control. Use environment variables or a
secrets manager.
</Warning>

## 2. Make your first call

<BaseUrl />

Every request needs the key in the `x-api-key` header. Health is the
simplest endpoint to verify connectivity — it's unauthenticated and lives
outside `/v1`.

<CodeGroup>

```bash curl
curl "$MARKETBOX_API_URL/health"
```

```ts TypeScript
const res = await fetch(`${process.env.MARKETBOX_API_URL}/health`);
console.log(await res.json());
```

</CodeGroup>

Then try a real call. List the services in one of the projects in your scope:

<CodeGroup>

```bash curl
curl "$MARKETBOX_API_URL/v1/projects/$MARKETBOX_PROJECT_ID/services" \
  -H "x-api-key: $MARKETBOX_API_KEY"
```

```ts TypeScript
const res = await fetch(
  `${process.env.MARKETBOX_API_URL}/v1/projects/${projectId}/services`,
  { headers: { 'x-api-key': process.env.MARKETBOX_API_KEY! } },
);
const { data, nextCursor } = await res.json();
```

</CodeGroup>

Then list the offerings on one of those services — an offering is a
bookable variant of a service, with its own duration and price:

<CodeGroup>

```bash curl
curl "$MARKETBOX_API_URL/v1/projects/$MARKETBOX_PROJECT_ID/services/$SERVICE_ID/offerings" \
  -H "x-api-key: $MARKETBOX_API_KEY"
```

```ts TypeScript
const res = await fetch(
  `${process.env.MARKETBOX_API_URL}/v1/projects/${projectId}/services/${serviceId}/offerings`,
  { headers: { 'x-api-key': process.env.MARKETBOX_API_KEY! } },
);
const { data, nextCursor } = await res.json();
```

</CodeGroup>

The response is:

```json
{
  "data": [
    {
      "offeringId": "off_01h2xcejqtfzcjxkvc4ay3pnh3",
      "serviceId": "srv_01h2xcejqtfzcjxkvc4ay3pnh3",
      "name": { "en": "60-minute private lesson" },
      "pricing": [
        {
          "ruleId": "r_9f2c1b04",
          "scope": "DEFAULT",
          "price": { "amount": 12000, "currency": "USD" }
        }
      ],
      "duration": { "type": "FIXED", "minutes": 60 },
      "attributeValues": [],
      "status": "ACTIVE"
    }
  ],
  "nextCursor": null
}
```

## 3. Create a booking

A booking always draws down a **funded order item** — you can't create one
without an order first. Once you have a `serviceId` and `offeringId`,
create an order with one `SINGLE_SESSION` item for it:

```bash
curl -X POST "$MARKETBOX_API_URL/v1/projects/$MARKETBOX_PROJECT_ID/orders" \
  -H "x-api-key: $MARKETBOX_API_KEY" \
  -H "content-type: application/json" \
  -d '{
    "clientId": "cli_456",
    "currency": "USD",
    "items": [
      {
        "skuType": "SINGLE_SESSION",
        "serviceId":  "srv_01h2xcejqtfzcjxkvc4ay3pnh3",
        "offeringId": "off_01h2xcejqtfzcjxkvc4ay3pnh3",
        "quantity": 1
      }
    ]
  }'
```

The order is nested under `data.order`, and its item(s) under `data.items[]`
— note the created order is `DRAFT` and unpaid, but that's enough to book
against (see [Accept payments with Stripe](/guides/accept-payments-with-stripe)
to charge for it later):

```json
{
  "data": {
    "order": {
      "orderId": "ord_01h2xcejqtfzcjxkvc4ay3pnh3",
      "status": "DRAFT",
      "total": { "amount": 12000, "currency": "USD" }
    },
    "items": [
      {
        "orderItemId": "oi_01h2xcejqtfzcjxkvc4ay3pnh3",
        "skuType": "SINGLE_SESSION",
        "quantity": 1,
        "quantityRemaining": 1,
        "unitPrice": { "amount": 12000, "currency": "USD" }
      }
    ]
  }
}
```

Now create the booking. Each service line references the `orderId` and
`orderItemId` from the order you just created — this is what ties the
schedule entry back to what paid for it. The body also carries explicit UTC
timestamps plus an IANA timezone — MarketBox derives the local date and
times for you (see [Timezones](/concepts/timezones)). This example uses
`locationType: "VIRTUAL"`, which needs no other location fields; `PHYSICAL`
and `TRAVEL_ZONE` bookings need more — see
[Create a single booking](/guides/create-a-single-booking) for the full
table of required fields per `locationType`.

```bash
curl -X POST "$MARKETBOX_API_URL/v1/projects/$MARKETBOX_PROJECT_ID/bookings" \
  -H "x-api-key: $MARKETBOX_API_KEY" \
  -H "content-type: application/json" \
  -d '{
    "supplierId": "sup_01h2xcejqtfzcjxkvc4ay3pnh3",
    "clientId":   "cli_456",
    "bookingStartUtc": "2026-06-01T17:00:00.000Z",
    "bookingEndUtc":   "2026-06-01T18:00:00.000Z",
    "bookingTz":       "America/New_York",
    "locationType":    "VIRTUAL",
    "capacity": 1,
    "services": [
      {
        "serviceId":  "srv_01h2xcejqtfzcjxkvc4ay3pnh3",
        "offeringId": "off_01h2xcejqtfzcjxkvc4ay3pnh3",
        "businessModelType": "SINGLE_BOOKING",
        "quantity": 1,
        "orderId":     "ord_01h2xcejqtfzcjxkvc4ay3pnh3",
        "orderItemId": "oi_01h2xcejqtfzcjxkvc4ay3pnh3"
      }
    ],
    "notes": []
  }'
```

You get back the created booking under `data`, plus the unique `bookingId`
you'll use for follow-on actions like rescheduling or changing status.

## 4. Handle errors

Every error response has the same envelope:

```json
{
  "code": "NOT_FOUND",
  "message": "Booking not found",
  "statusCode": 404,
  "requestId": "3f7c1a9e-5b2d-4e8a-9f01-2c6d8b4a7e13"
}
```

The `requestId` is also returned in the `X-Request-Id` response header —
include it when contacting support. See [Errors](/concepts/errors) for the
full code list.
