## Authentication

Every endpoint under `/v1` requires an `x-api-key` header. The
playground accepts your key in the authorization slot.

See [Authentication](/concepts/authentication) for the full model.

```http
x-api-key: mb_test_********************************
```

## Conventions

The same shapes show up everywhere:

- **List responses** wrap items in `{ data: [...], nextCursor }`. See
  [Pagination](/concepts/pagination).
- **Single-item responses** wrap the item in `{ data: {...} }`.
- **Errors** are returned with a shared envelope. See
  [Errors](/concepts/errors).
- **Times** are ISO 8601 strings in UTC, paired with an IANA timezone
  identifier on resources that have a customer-facing local time.
  See [Timezones](/concepts/timezones).
- **Money** is `{ amount: integer, currency: 3-letter ISO }` — amounts
  are integers in the currency's **minor unit** (cents, pence, etc.).

## The raw spec

If you'd rather work directly from the OpenAPI document — generating a
client, importing into Postman, or writing your own playground — pull
it straight from the running service:

```bash
curl "$MARKETBOX_API_URL/v1/openapi.json"
```

The same document is bundled with this site and can be fetched at
[`/api-reference/openapi.json`](/api-reference/openapi.json).

<Tip>
  The spec is OpenAPI 3.0. Tools like
  [openapi-typescript](https://github.com/drwpow/openapi-typescript),
  [openapi-generator](https://openapi-generator.tech/), and
  [orval](https://orval.dev/) all consume it directly.
</Tip>
