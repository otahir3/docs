## Holds, the double-booking guard — and a breaking change to `POST /holds`

Supplier time is now exclusive at the write layer, and you can **hold** it while a customer pays. A hold works on any supplier time — a single session (no package, no slate), a cherry-picked subset of a package slate, or a whole slate — and `POST /holds/{reservationId}/convert` turns it into confirmed bookings. Alongside it, every write that claims supplier time now passes through an occupancy guard, so two bookings can never overlap on the same supplier.

**Breaking**

Each entry in `intervals[]` on `POST /v1/projects/{projectId}/holds` now mirrors the `POST /bookings` location contract exactly. **`bookingTz` and `locationType` are required**, and `locationType` decides which of `locationId` / `latitude` / `longitude` / `address` must come with them.

Before:

```json
{
  "intervals": [
    {
      "supplierId": "sup_01kv60qgnef2kt3pvqgwmkbzfr",
      "startUtc": "2026-07-15T14:00:00.000Z",
      "endUtc": "2026-07-15T15:00:00.000Z",
      "locationId": "stz_01kv60qgs4e4nbjhzradnqtj0h"
    }
  ]
}
```

After:

```json
{
  "intervals": [
    {
      "supplierId": "sup_01kv60qgnef2kt3pvqgwmkbzfr",
      "startUtc": "2026-07-15T14:00:00.000Z",
      "endUtc": "2026-07-15T15:00:00.000Z",
      "bookingTz": "America/Toronto",
      "locationType": "TRAVEL_ZONE",
      "locationId": "stz_01kv60qgs4e4nbjhzradnqtj0h",
      "latitude": 43.6532,
      "longitude": -79.3832,
      "address": {
        "addressOneLine": "100 Queen St W, Toronto, ON M5H 2N2, Canada",
        "streetNumber": "100",
        "streetName": "Queen St W",
        "city": "Toronto",
        "state": "ON",
        "country": "CA",
        "zipCode": "M5H 2N2"
      }
    }
  ]
}
```

An interval without `bookingTz` or `locationType` is now a `400 VALIDATION_ERROR`. This applies to the heartbeat too — extending a hold re-sends the same `intervals`, so they must carry the same fields.

**Why**

Convert rebuilds the booking from the **reservation alone** — never by re-reading a slate that may have expired while the customer was paying. A hold that carried only a `locationId` could not say whether that id was a `Location` (`loc_…`) or a supplier travel zone (`stz_…`), so converting a mobile / in-home hold failed with `404 Location stz_… not found`, and a `TRAVEL_ZONE` booking's mandatory coordinates and address were never held at all. Travel-zone checkouts now work end to end.

**New**

- **`POST /holds`** — hold supplier time with `intervals` (single session or any explicit time), `slateId` (a whole package slate), or `slotIds` (a subset). All-or-nothing, in one transaction. Pass `reservationId` to **extend** an existing hold: the checkout heartbeat pushes `heldUntil` out and returns the same `reservationId` instead of minting a second hold.
- **`POST /holds/{reservationId}/convert`** — one idempotent endpoint for both shapes; it branches on the order item's `skuType` (`SINGLE_SESSION` books the one held interval; `PACKAGE` books every held interval and draws down credits). Safe to call straight from a Stripe webhook.
- **`GET /holds/{reservationId}`** and the `201` from `POST /holds` now **echo the full interval shape** — `bookingTz`, `locationType`, `locationId`, `latitude`, `longitude`, `address` — so you can verify exactly what convert will build.
- **`POST /holds/{reservationId}/release`** — free the time immediately when a checkout is abandoned. Idempotent, never an error.
- **Occupancy guard** — `409 SLOT_HELD` / `SLOT_BOOKED` on any write that collides with a live claim. The body names the blocking `reservationId` or `bookingId` and tells you what to do with it.
- **Conflict responses now carry the full error envelope.** Every `409` conflict and hold-lifecycle body (`SLOT_HELD`, `SLOT_BOOKED`, `HOLD_EXPIRED`, `RESERVATION_*`, and the slate codes) now includes `statusCode` and `requestId` alongside `code` and `message`, matching every other error. Purely additive — nothing was removed or renamed. If you were branching on the HTTP status because `body.statusCode` was missing on these, you no longer have to. See [Errors](/concepts/errors).

**What this means for you**

- If you build `intervals` by hand, **add `bookingTz` and `locationType` before your next deploy** — including in your heartbeat call.
- If you hold by `slateId` or `slotIds`, **nothing changes**: the slate's slots already carry every location field, and the hold now copies them onto the reservation for you.
- If you hold time, you must **convert** it — `POST /bookings` and `POST /orders/{orderId}/package-bookings` will not consume a hold, not even your own, and return `409 SLOT_HELD` naming your own `reservationId`.

Full walkthrough, a travel-zone worked example, and a status/code troubleshooting table: [Hold slots during checkout](/guides/hold-slots-for-checkout). The guard itself: [Concurrency](/concepts/concurrency).

## Catalog management endpoints

You can now manage your service catalog directly through the API. This release adds full create, read, update, and delete (CRUD) support for services, their offerings, and the business models attached to them — so you can build, sync, and automate catalogs without using the dashboard.

**New**

- **Services** — Create, list, retrieve, update, soft-delete, and toggle status for services on a project. See [Services](/api-reference/introduction).
- **Offerings** — Add offerings to a service, list them, fetch a single offering, update or soft-delete it, and change its status.
- **Business models** — Attach pricing/business models to a service, list them, update them, and toggle active status.

**What this means for you**

- Sync your catalog from an external system of record on a schedule.
- Build admin tooling that lives outside the MarketBox dashboard.
- Programmatically enable or disable offerings as inventory and availability shift.

All new endpoints are project-scoped and follow the existing [authentication](/concepts/authentication), [pagination](/concepts/pagination), and [error](/concepts/errors) conventions. Browse the full list under [API reference → Endpoints](/api-reference/introduction).

</Update>
