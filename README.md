# MarketBox API docs

The user-facing documentation site for the MarketBox public API. Built
on [Mintlify](https://mintlify.com).

## Structure

```
docs/
├── docs.json                 # Mintlify config + navigation
├── index.mdx                 # Landing page
├── quickstart.mdx            # First-call walkthrough
├── glossary.mdx              # Terms, and the one place "provider" etc. may appear
├── concepts/                 # Cross-cutting guides (auth, pagination, errors, ...)
├── guides/                   # End-to-end walkthroughs (holds, packages, Stripe, ...)
├── resources/                # Per-resource overviews (bookings, orders, suppliers, ...)
├── changelog/overview.mdx    # One <Update> block per API release, newest first
├── snippets/                 # Reusable MDX fragments (base URL)
├── api-reference/
│   ├── introduction.mdx      # Reference overview
│   ├── openapi.json          # OpenAPI 3.0 spec — source of all endpoint pages (generated)
│   └── docs-contract.json    # Id prefixes, error codes, hosts, terminology (generated)
└── scripts/                  # Drift checker: `npm run check` (rules in scripts/rules/)
```

The endpoint pages in the "API reference" tab are **auto-generated by
Mintlify from `api-reference/openapi.json`** — there is no MDX file per
endpoint. To change what's documented for an endpoint, change the
OpenAPI spec at its source (the `apps/open-api-mb` workspace in the
`mb-core` repo) and resync as below.

## Regenerating the OpenAPI spec

Both files under `api-reference/` are **generated artifacts committed in
`mb-core`** (`apps/open-api-mb/openapi.json` and `docs-contract.json`),
where CI fails any change to a route that does not regenerate them. Do not
edit them here, and do not export them from a running server — copy the
CI-verified files with the sync scripts:

```bash
# From the mb-core repo, on the branch you are documenting.
# Each script builds @mb-core/types and @mb-core/db first — that prefix is
# load-bearing, the generator reads compiled output.
pnpm --filter @mb-core/open-api-mb openapi:check      # "up to date" or stop here
pnpm --filter @mb-core/open-api-mb contract:check
pnpm --filter @mb-core/open-api-mb openapi:sync   -- path/to/docs/api-reference/openapi.json
pnpm --filter @mb-core/open-api-mb contract:sync  -- path/to/docs/api-reference/docs-contract.json
```

`openapi:sync` refuses to copy a spec that differs from what the routes
produce; if it does, run `openapi:write` in `mb-core`, commit that, and
sync again. No hand-patching is needed afterwards: `info`, `servers`,
`securitySchemes` and `security` come from the source app. Both files are
LF-only and byte-identical to the `mb-core` copies (`.gitattributes` pins
that), so the diff on every sync is the real change and nothing else.

Ship the spec, the contract, and any prose that depends on them **in one
commit** — the drift checker validates request-body examples in MDX against
`openapi.json`, so a page that documents a new field fails until the spec
that carries it lands with it. Add a `changelog/overview.mdx` entry for
anything an integrator can observe.

## Validating

Run the drift checker before every push. CI runs the same two commands on
pushes to `main` and on pull requests (`.github/workflows/docs-check.yml`):

```bash
npm test          # unit tests for the checker (on Windows: node --test scripts/check-docs.test.mjs)
npm run check     # must end with "docs check passed"
```

The checker rejects paths that are not in the spec, unknown id prefixes,
error codes that are neither in the contract nor a spec enum, hosts outside
the allowlist (use `example.com`), non-`MARKETBOX_*` env vars, banned
terminology, and request-body examples that do not match the schema. Rules
live in `scripts/rules/`; each one has a `bad.mdx` fixture showing what it
catches.

Then Mintlify's own checks (the CLI needs Node 20.17 or newer):

```bash
npm i -g mint
mint openapi-check api-reference/openapi.json
mint broken-links
```
