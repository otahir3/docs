# MarketBox API docs

The user-facing documentation site for the MarketBox public API. Built
on [Mintlify](https://mintlify.com).

## Structure

```
docs/
├── docs.json                 # Mintlify config + navigation
├── index.mdx                 # Landing page
├── quickstart.mdx            # First-call walkthrough
├── concepts/                 # Cross-cutting guides (auth, pagination, errors, ...)
├── resources/                # Per-resource overviews (bookings, orders, ...)
└── api-reference/
    ├── introduction.mdx      # Reference overview
    └── openapi.json          # OpenAPI 3.0 spec — source of all endpoint pages
```

The endpoint pages in the "API reference" tab are **auto-generated by
Mintlify from `api-reference/openapi.json`** — there is no MDX file per
endpoint. To change what's documented for an endpoint, change the
OpenAPI spec at its source (the `apps/open-api-mb` workspace in the
`mb-core` repo).

## Regenerating the OpenAPI spec

The `openapi.json` in this repo is a snapshot of what `open-api-mb`
serves at `/v1/openapi.json`. To update it:

```bash
# From the mb-core repo
pnpm --filter @mb-core/types build
pnpm --filter @mb-core/db build
pnpm --filter @mb-core/open-api-mb dev
# In another shell, while the server is running:
curl http://localhost:3002/v1/openapi.json \
  | node -e "let d=''; process.stdin.on('data',c=>d+=c); process.stdin.on('end',()=>console.log(JSON.stringify(JSON.parse(d), null, 2)))" \
  > path/to/mb-docs/docs/api-reference/openapi.json
```

After regenerating, re-apply the manual enrichments at the top of the
file (`info.description`, `servers`, `components.securitySchemes`,
`security`) — these are not in the live spec and must be re-added until
the source app emits them.

## Local preview

```bash
npm i -g mint
mint dev
```

Open <http://localhost:3000>.

## Validating the spec

```bash
mint broken-links
mint openapi-check api-reference/openapi.json
```

## Publishing

Changes pushed to the default branch deploy automatically via the
Mintlify GitHub app.
